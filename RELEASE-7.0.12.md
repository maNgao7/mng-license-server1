# TikMnG 7.0.12: Reduced Idle Overlay Traffic

## Scope

This release changes launcher widget/media transport and the server relay cache policy. All game packages, including the approved Profile Contest 0.3.0, remain unchanged. Existing overlay URLs, licenses and user settings are retained. No uninstall is required.

- Widgets opt into revision-based long polling. An unchanged snapshot produces an empty 204 after ten seconds; a changed snapshot wakes the request. Old publishers and old clients still receive ordinary JSON.
- Root timestamps, running-timer remaining milliseconds and PK freshness timestamps do not invalidate an otherwise unchanged snapshot. Scores, deadlines, profiles, settings and events still do. Countdown rendering continues locally.
- Authenticated media long polls wait up to ten seconds when idle. Gift events are still scoped and delivered promptly. Existing playback receipts, retries and hidden entry-source behavior are retained.
- Completely buffered short revision-addressed owned media may reuse a native element: at most three items / 48 MiB, at most 24 MiB each, at most 180 seconds. There is no eager prefetch, transcoding or forced download of remote URLs.
- Hidden previews pause requests. Broadcast sources are deliberately NOT stopped based only on document visibility, because Live Studio may label a working source hidden.
- Immutable original portrait responses now retain their private 24-hour browser cache through the relay. Revision-addressed media accepts the old one-hour or new 24-hour private policy. State, HTML, errors and other users' data are never publicly cached.
- An administrator-only `/api/admin/http-traffic` endpoint separates fixed HTTP response categories. It keeps 48 hourly memory buckets, no IP, token, username or message content. It resets on process restart and measures response bodies, not invoice totals, TLS or HTTP headers.

## Validation

- 1,072 launcher tests and 83 server tests, no failures or skips.
- Actual packaged Windows executable: IPC, gifts, queued change response, settings preservation, Profile Contest launch and Okur/Ema non-silent WASM audio.
- Real Chrome browser through the local WebSocket relay, with no Render traffic generated by that benchmark.
- Twelve-second idle timer comparison: 17 requests / 8,738 response-body bytes before; 3 requests / 567 bytes after (93.51% fewer state body bytes). The timer continued counting down.
- A new wheel gift appeared in 533 ms; PK score changes propagated. The exact timings vary by hardware and connection.
- A complete short video transferred 18,010 bytes on first play and zero additional video bytes on the second play; the same native media element was reused.
- Authentication, account isolation, cancellation, request caps, cache eligibility, range requests, duplicate gifts, timer additions and hidden entry delivery are covered.

These measurements are controlled examples, NOT a guaranteed percentage of the total Render bill. Different videos, changing scores, independent browser sources and older launchers will change the result. No new hosting subscription or automatic spending limit was enabled.

## Rollout

Verify the normalized installer, portable executable, blockmap and update feed against `manifest-7.0.12.json` before publishing. GitHub is the primary artifact source; Drive is a backup. Deploy the server commit on Render and update launchers normally to enable the complete change protocol. Refresh existing Live Studio browser sources once after updating so they load the new transport script; the URLs do not change. Server cache fixes also benefit compatible older launchers. Keep game catalog URLs and the previous release intact for rollback.

No paid gifts were sent, and other customers' physical computers were not tested. External TikTok availability remains a dependency. Windows publisher signing is not configured.
