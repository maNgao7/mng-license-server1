# Teke Tek Profil — 0.5.8

## Rules
- Select two distinct profiles by clicking the picture cards. The × button clears a side. In the game controls, each picture opens a tall participant list on its own side of the window. The photo picker has gift sender, chat and like tabs, backed by real observed participants and the shared portrait cache. The copied widget has no editing controls.
- The default gifts are one-coin Gül/Rose (5655) on the left and one-coin TikTok (5269) on the right. Each side can select a distinct gift from the catalog.
- Each side can set a positive whole number of points per gift. A completed series multiplies this value by its repeat count. For example, a Gül worth 50 points adds 150 for three repeats. A blank setting uses the normalized total coin value. Completed gifts are deduplicated across rounds and reconnects to the same account within the game session.
- The timer determines the winner. The result clears the losing slot immediately and keeps the winner on their original side. For three seconds the winner appears at center with a crescent-and-star crest, Ottoman-inspired gold wings, rays and sparks. Reduced motion holds the same composition with still wings and no moving effects. A draw keeps both players in place.
- The broadcast widget has a transparent, tightly fitted stage (at most 448×236 px), square portraits up to 156 px and gift icons up to 28 px. Each name, or “Bir oyuncu seç” for an empty slot, sits directly below its portrait. Smaller canvases shrink the portraits without moving their labels. The keyed control preview uses a 250 px tall canvas.
- The clock replaces VS between the portraits. Pausing displays “DURAKLATILDI” centrally above the frozen remaining time. The red/green score rail starts and ends at the outer portrait boundaries; its dividing marker follows the score share. A small 10×13 px CSS flame appears inside the leading segment near the divider during an active round. Ties, pause and results have no flame; reduced motion holds the flame still and disables the marker transition. In the keyed preview, clicking a portrait or its caption opens selection; the selection text appears only below the portrait.
- Both the local test page and launcher control page offer Saniye/Dakika duration units. The existing default remains 120 seconds, and switching units preserves that duration (120 seconds ↔ 2 minutes). Decimal minutes are supported (1.5 minutes → 90 seconds), rounded to whole seconds. The existing range remains 10–3600 seconds (up to 60 minutes). Blank or out-of-range input cannot start a round. Requests, snapshots and integrations still use `durationSeconds`; no server or scoring schema changes are required. Incoming snapshots only refresh the input when the server duration changes, preserving edits for the next round.

## Launcher integration
`lib/profile-duel-launch.cjs` in the manager creates `createLauncherServer` from `src/server.mjs`. The launcher owns the live connection and supplies `sharedGameEvents` as `(type, payload, metadata)`. The game accepts live-source events for the selected channel. Gifts use the event ID, gift ID or name, completion fields, repeat count and coin metadata.
Profiles use the launcher's `widgetPortraits` cache under `userData/widget-portraits-v1`. Nicknames and usernames are separate. A pending cache entry (`v=0`) preserves a portrait already received from an event. Picker rows stay mounted during counter updates. Failed picker portraits fall back to the shared cache with four bounded retries. Missing photos show initials.

Supply `connectLive` to allow opening without a publisher. The game waits for account selection before accepting shared events. Pass `autoSelectOwner: false` when launching with a known publisher and both player slots should start empty. Account changes leave both player slots empty.

The returned `getBroadcastState()` reads the current widget snapshot. `getChannel()` returns the current publisher username or an empty string while waiting for selection. Supply `getBroadcastURL(username)` to enable HTTPS copying. The callback receives the same username as `getChannel()`. Return the public HTTPS URL when ready and `null` while preparing it. The key-protected `/api/meta` reports `broadcastUrlSupported` and includes `broadcastUrl` when valid. Without the callback, the copy control uses the local read-only `/widget` address for testing on the same computer. Both copy paths omit the control key.
The package, lockfile and game-owned widget manifest report version 0.5.8. Entry points retain their existing paths.

Gift settings survive account changes in the same game window. The launcher can persist them through `onGiftConfig` and restore them through `giftConfig`. The manager stores the settings under `profile_duel_gifts_v1` in its user data. The optional point fields are `rosePointsPerGift` and `tiktokPointsPerGift`. Missing fields and `null` use coin scoring. The game does not write account credentials or rankings.

## Verification
Run `tests/release-gate.ps1`. The gate exercises configured and default scoring, replay handling, publisher changes, HTTPS copy readiness, photo selection, the full timed round, and local HTTP/SSE transport. Browser checks cover the 1152×760 launcher wrapper, desktop, mobile, 960×250 and 320×180 canvases; transparent stage bounds; portrait/bar alignment; small gifts; central pause state; both leading sides and ties; motion preferences; and a relay-shaped result. Duration tests submit minutes and legacy seconds through both real local HTTP endpoints, verify pause/resume/reset, preserve edited values across snapshots, and reject invalid input. fast-check runs 1000 replay/scoring sequences and 1000 minute/second round trips with seed 20261115.
Browser screenshots are saved under `tests/artifacts/`: `duel-compact-empty.png`, `duel-compact-running.png`, `duel-compact-paused.png`, `duel-tall-compact.png`, and `duel-compact-victory-{flap,open,reduced}.png`. The cached portraits and gift events are local test fixtures.
Real gift delivery and actual TikTok portraits require a separate observed live test. No public release is authorized by these local checks.
